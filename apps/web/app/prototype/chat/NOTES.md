# Chat prototype verdict

问题：聊天页面应该采用什么结构？

结论：保留变体 12「三段工作台」作为正式实现方向。它提供窄图标 Rail、对话列表和稳定的聊天主区域，未来可扩展多对话、Provider 设置、记忆入口。

正式实现约束：

- Composer 固定在对话区域底部，始终可见。
- 页面必须响应式，移动端优先。
- 移动端隐藏或折叠侧栏，不能挤压聊天内容。
- 移动端 Header 使用紧凑层级，不直接复用桌面 Header 的全部信息。
- 移动端通过顶部左侧 Hamburger 打开覆盖式对话 Drawer。
- 未配置 BYOK 时仍停留在 `/chat`，展示空状态卡片并引导至 `/settings/provider`。
- Composer 使用最多 5 行的多行输入；桌面 Enter 发送、Shift+Enter 换行；手机使用发送按钮。
- 原型切换条属于评审工具，正式页面不包含它。

原型仅用于视觉讨论，不直接晋升为生产代码。
